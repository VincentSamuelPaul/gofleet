# GoKura

**A lightweight, gRPC-based in-memory KVStore with caching and execution-time benchmarking.**

GoKura is a simple key-value store implemented in Go, using gRPC for networked access. It supports a **fast in-memory cache** and a backing store (map), allowing you to **benchmark cache hits vs cache misses**. This project is designed as an educational and demonstrative prototype, inspired by Redis.

---

## Features

* **gRPC server** for networked key-value operations
* **In-memory cache** for fast retrieval
* **Backing store** for cache misses
* **Execution time logging** for cache hits vs misses
* **Unit tests** for core functionality
* Simple Go client to **test cache and measure performance**

---

## Getting Started

### Prerequisites

* Go 1.24+
* `protoc` (Protocol Buffers compiler)
* gRPC Go plugin

---

### Project Structure

```
GoKura/
├─ cache/           # LRU Cache types and algorithm
|  └─ cache.go      
├─ client/          # Go client to test the server

│  └─ kvstore.proto

│  └─ kvstore.proto

├─ go.sum

```

---

### Running the Server

1. Navigate to the server folder:

```bash
cd server
go run server.go
```

* The server will start listening on port `50051`.
* Logs will show **cache hits and misses** along with execution times.

---

### Running the Client

1. In a new terminal, navigate to the client folder:

```bash
cd client
go run client.go
```

2. The client will:

   * Prepopulate the backing store
   * Preload some keys into cache
   * Measure **execution time** for cache hits and cache misses

Example output:

```
[MISS] Key=key7, Found=true, Value=value7, ExecutionTime=5.301416ms
[HIT]  Key=key3, Found=true, Value=value3, ExecutionTime=133.083µs
[HIT]  Key=key1, Found=true, Value=value1, ExecutionTime=192.042µs
```

* **Cache miss**: key not yet in cache → loaded from backing store
* **Cache hit**: key already in cache → microsecond-level access
