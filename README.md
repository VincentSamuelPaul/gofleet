# GoFleet

A lightweight distributed systems toolkit with LoadBalancer and KeyValueStore written in Go.

---

## 🚀 Features

### Load Balancer

* Round-robin request distribution
* Node health checks via `/status`
* Worker pool and job queue system
* Simulated CPU-intensive tasks (prime number finder)

### KVStore (new)

* gRPC-based key-value storage
* In-memory cache + map-based backing store
* Execution-time benchmarking (cache hit vs miss)
* Lightweight, Redis-inspired design

---

## 🧠 How It Works

### Load Balancer Flow

1. **Load Balancer** listens on port `3000` and forwards `/work` requests to healthy nodes (`3001`, `3002`, ...).
2. **Nodes** each maintain a buffered queue and worker pool.
3. Workers execute CPU-heavy tasks concurrently.

### KVStore Flow

1. **Server** hosts a gRPC key-value API (`Set`, `Get`).
2. **Cache** provides microsecond-level access on repeated reads.
3. **Misses** fetch from map storage and populate the cache.
4. Execution times are logged for benchmarking.

### Running the loadbalancer

1. Navigate to the loadbalancer folder:

```bash
cd gofleet/loadbalancer

# Build everything
make build

# Start load balancer and all nodes
make start-all

# Run load tests
make run-tests

# Stop everything
make stop-all
```

---

### Running the kvstore server

1. Navigate to the server folder:

```bash
cd gofleet/kvstore/server
go run server.go
```

* The server will start listening on port `3000`.
* Logs will show **cache hits and misses** along with execution times.

---

### Running the kvstore client

1. In a new terminal, navigate to the client folder:

```bash
cd client
go run client.go
```

2. The client will:

   * Prepopulate the backing store
   * Preload some keys into cache
   * Measure **execution time** for cache hits and cache misses

Example output:

```
[MISS] Key=key7, Found=true, Value=value7, ExecutionTime=5.301416ms
[HIT]  Key=key3, Found=true, Value=value3, ExecutionTime=133.083µs
[HIT]  Key=key1, Found=true, Value=value1, ExecutionTime=192.042µs
```

* **Cache miss**: key not yet in cache → loaded from backing store
* **Cache hit**: key already in cache → microsecond-level access
